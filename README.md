# hxyfront-62001 船舶双岗离线值班台账

面向船舶**驾驶台 × 机舱**双岗的值班记录系统。两岗各开一份值班页，断网时各自在本地继续记参数、异常和处理结果；恢复在线后按操作日志合并，同一时点两个读数进入待复核区，未裁决前拦住交班。

## 功能一览

- **双岗值班页**：顶部切换「驾驶台 / 机舱」（`#bridge` / `#engine`，可在两个浏览器标签页同时打开模拟两岗终端）；每页都能新增 **参数读数 / 异常 / 处理结果**。
- **断网离线记录**：点击岗位徽标可切换断网。断网期间数据只写本岗本地台账与出站队列，不丢数据；恢复在线后点「同步合并」。
- **同步合并规则**：两岗所有操作按时间全序回放（同 opId 幂等，绝不重复），记录按 **设备 + 参数 + 船内记录时刻** 归并；同一时点出现两个有效读数自动进入**待复核区**，裁决后未采用的读数标记为「已被修订」而不是删除。
- **交接班摘要**：列出累计值衔接与遗留事项。本班存在未裁决的重复读数时，摘要标「不完整」并**拦住交班**（封存按钮禁用 + 提交时二次兜底）。
- **船内时间**：所有记录时刻使用船内时间，支持时区偏移修正；换班后累计值（如燃油消耗）与未闭环异常按船内时间继续衔接到下一班。
- **旧样例自动迁移**：旧轮机页 3 行无稳定编号样例先冻结原始快照，再逐行迁入；确定性编号（`运行号+行号+类型`）保证中断/重开/双端重放都不重复，迁移游标按行提交，中途关闭只保留原件与已完成部分，重开后自动续跑。
- **权限分层**：普通轮机员对任何记录（含已封存）只能**补充说明**；领导复核后可**修订已封存记录**（原版保留为 superseded，修订链可追溯）或作废。封存班次不再接受新记录。
- **不可改写审计**：新增、补说明、异常闭环、冲突裁决、修订、作废、封存全部生成 append-only 审计，对端同步来的操作也会在双方留痕（标注来源）。

## 数据与存储

数据均在浏览器 `localStorage`：

| 键 | 内容 |
| --- | --- |
| `dlw.db.bridge` / `dlw.db.engine` | 各岗台账（记录、班次封存、裁决、已应用 opId、迁移进度） |
| `dlw.outbox.*` | 出站操作日志（同步后标记 synced 并留底，用于全序重放） |
| `dlw.audit.*` | 各岗 append-only 审计 |
| `dlw.legacySnapshot.v1` | 旧样例冻结快照（原件永不改动） |
| `dlw.session` | 双岗值班员档案、角色、船内时钟偏移、在/离线状态 |

> 说明：本应用是纯前端离线原型，「双岗同步」在同一浏览器内用两份本地库 + 出站日志模拟，后续接入船队服务端时，把 `syncStations` 换成与服务端交换 outbox 即可，操作日志/冲突/审计模型无需改动。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62001  （#engine 机舱 / #bridge 驾驶台）
npm run typecheck
npm run build
npm test           # 逻辑场景模拟（sim.ts）+ jsdom 渲染冒烟
```

### 建议的手动体验路径

1. 打开机舱页，等待顶部「旧样例迁移」自动跑完（也可取消自动续跑、关闭页面再打开验证断点续跑）。
2. 把驾驶台切到「断网」，两岗在同一分钟录入 **主机 / 主机转速 / 相同船内时刻但不同数值**。
3. 恢复在线 → 同步合并，待复核区出现一组冲突；交接摘要显示「不完整」，封存交班被拦住。
4. 裁决采用其中一个读数后，摘要变完整，封存交班。
5. 切换到下一班（或修改船内时钟偏移），查看累计值与遗留异常继续衔接；录一条处理结果闭环异常。
6. 切到「领导」角色修订一条已封存记录，再切回普通轮机员验证只能补说明；展开审计表查看不可改写记录。
