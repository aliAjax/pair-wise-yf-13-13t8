# hxyfront-62001 船舶双岗值班离线台账

面向船舶值班的前端记录系统：**驾驶台与机舱各开一份值班页**，断网时两边各自记录，恢复联网后按「设备 + 船内记录时刻」合并；同一时点出现两个读数进入**待复核区**，未经领导裁决前交接摘要标出不完整并**拦住交班**。数据保存在浏览器本地（localStorage），结构按船队统一管理预留扩展。

## 功能对照

| 需求 | 实现 |
| --- | --- |
| 双岗值班页 | 「驾驶台值班页」「机舱值班页」两个标签页，各自的设备/参数看板、异常与处理结果、本班累计增量 |
| 断网双记 | 页头可模拟断网；离线记录先进本岗「待发箱」，恢复联网（或手动点同步）自动补传 |
| 同步合并 | 以 `设备 + 记录时刻（精确到分钟）` 为键：读数一致自动合为一条并保留双来源；读数不同进入待复核区 |
| 待复核拦截交班 | 领导可在复核区选 A/B/取平均/自定义并填写依据；有待复核或未同步记录时，交接摘要标红且交班按钮禁用，拦截动作也写审计 |
| 旧样例自动迁移 | 旧轮机页 3 条无编号样例按行内容指纹生成确定性 ID（`lg-…`）逐行迁入；原数据整体另存只读快照；迁移可随时中断，重开自动续传，已完成行按 ID 去重，绝不重复 |
| 角色权限 | 值班领导可裁决复核、可修订已封存记录（必填原因、原值留版本）；普通轮机员只能记录与**补说明**（仅追加） |
| 不可改写审计 | 所有变化追加为审计事件，事件间用 `prevHash` 哈希链串联；界面无修改/删除入口，可导出 JSON，篡改任一条立即被校验发现 |
| 换班衔接 | 交班封存本班、生成班次快照：航次累计值（燃油/滑油/工时）与遗留事项按船内时间带入下一班摘要 |
| 船内时间 | 支持相对系统时钟设置分钟偏移（跨时区），调整只影响之后记录，动作入审计 |

## 技术栈

React 19 + Vite 7 + TypeScript（严格模式），无额外运行时依赖；状态用 reducer + Context，落盘 localStorage。

## 目录结构

```
src/
  types.ts                 数据模型（记录/冲突/班次快照/审计事件/迁移状态）
  core/
    time.ts                船内时间、4 小时班次编号
    hash.ts                稳定序列化 / FNV 哈希 / 内容指纹
    legacy.ts              旧样例行解析（确定性编号、读数/异常启发式解析）
    store.tsx              reducer：离线 outbox、同步合并、复核、权限、交班、审计链
  components/
    WatchPage.tsx          驾驶台/机舱值班页
    ReviewPage.tsx         同步状态与待复核区裁决
    HandoverPage.tsx       交接摘要、拦截、封存班次历史
    HistoryPage.tsx        按设备/班次/状态筛选；领导修订、轮机员补说明
    AuditPage.tsx          审计链校验、筛选、导出
    SettingsPage.tsx       身份/船钟/迁移进度/原数据快照/重置
    ui.tsx                 Toast、徽标、弹窗等
```

## 本地运行

```bash
npm install
npm run dev          # http://localhost:62001
```

其他命令：

```bash
npm run typecheck    # tsc 严格检查
npm run test:logic   # reducer 逻辑测试（迁移幂等/合并/冲突/拦截/权限/审计链）
npm run build
```

## 体验路径建议

1. 打开应用后到「设置 / 迁移」观察旧样例逐行迁入；可在中途点「暂停」再「续传」验证无重复。
2. 页头切到「断网中」，分别在驾驶台、机舱记录同一设备同一时刻：先记一致读数（自动合并），再记不一致读数（进待复核）。
3. 恢复联网 → 打开「同步 / 待复核」，以普通轮机员身份看不到裁决操作；切回值班领导后裁决。
4. 未裁决前去「交接班」会被拦截；裁决后再交班，查看封存班次与累计/遗留衔接。
5. 到「台账历史」对「旧样例迁移」记录试领导修订与轮机员补说明；「审计记录」页导出并校验哈希链。
